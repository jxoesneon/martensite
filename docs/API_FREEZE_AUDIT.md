# API Freeze Audit — v0.18.0

**Status:** Current (supersedes the v0.11.0 audit, preserved as Appendix A)

This document records the API-freeze posture of the Martensite workspace as
of the v0.18.0 milestone. It is the policy companion to
[`API_SURFACE_AUDIT.md`](API_SURFACE_AUDIT.md), which contains the
machine-enumerated per-crate surface (generated by
`scripts/api_surface_audit.py`).

## 1. Scope

- **Publishable crates:** 33 — every workspace member under `crates/`
  without `publish = false`. Excluded: `martensite-bevy`,
  `martensite-godot`, `martensite-media-test`, `martensite-render-test`,
  `martensite-text-reference` (all `publish = false`), plus `tools/`,
  `examples/`, `benches/`, and the `stubs/` namespace-reservation crates
  (not workspace members).
- **Surface size:** see the generated totals in `API_SURFACE_AUDIT.md`
  (~1,600 nameable public items across the 33 crates as of v0.18.0,
  including re-exports).
- **Classification:** each item is STABLE, EXPERIMENTAL, or
  VENDORED-upstream per the rules embedded in
  `scripts/api_surface_audit.py` (`CRATE_TIER`, `EXPERIMENTAL_RULES`).

## 2. Lint Enforcement

### Workspace-level lints (`[workspace.lints.rust]`)

```toml
[workspace.lints.rust]
unsafe_code = "deny"
missing_docs = "deny"
```

All workspace crates inherit these via `[lints] workspace = true`.

### `#![allow(unsafe_code)]` — audited FFI exceptions (TEN crates)

The authoritative unsafe-exception list is the ten crates enumerated in
`AGENTS.md` ("Font fallback architecture"). All other crates maintain
`unsafe_code = "deny"` (most via crate-level `#![forbid(unsafe_code)]`,
which cannot be overridden).

1. `martensite-access-platform` — mobile accessibility FFI (UIKit /
   `accesskit_ios` on iOS, JNI / `accesskit_android` on Android).
2. `martensite-font-fallback` — DirectWrite / CoreText / Fontconfig FFI.
3. `martensite-clipboard-platform` — NSPasteboard / Win32 / X11 FFI.
4. `martensite-media-platform` — IOSurface / DXGI / dmabuf surface import.
5. `martensite-host` — `dlopen` / `LoadLibrary` dynamic loading.
6. `martensite-cosmic-text` — vendored upstream fork (cosmic-text); also
   `#![allow(missing_docs)]` + `#![allow(clippy::all)]`.
7. `martensite-accesskit-winit` — vendored `accesskit_winit` 0.34.0 patched
   for winit 0.31.0-beta.3; **temporary**, removed once upstream supports
   winit 0.31.
8. `martensite-vello` — vendored `netrender-vello` 0.10 (Vello 0.10 on
   wgpu 30); same exemptions as cosmic-text.
9. `martensite-shell` — DWM / NSVisualEffectView / Liquid Glass FFI;
   Wayland CSD is safe Rust.
10. `martensite-godot` — `godot` (gdext) FFI boundary; `publish = false`
    and excluded from the default workspace build.

### Doc-example requirement

Every public item in a publishable crate carries a compilable doctest
example (enforced by `cargo test --doc`). Exempt: `martensite-cosmic-text`
and `martensite-vello` (vendored forks; `#![allow(missing_docs)]` +
`#![allow(rustdoc::broken_intra_doc_links)]`).

## 3. Feature-Flag Inventory (`unstable-*` final inventory)

The v0.18.0 audit grepped every crate manifest for feature flags. There
are **no `unstable-*` feature flags in the workspace**, and this is the
deliberate final state for the pre-freeze line:

- Under SemVer §4, the entire `0.x` surface is already unstable by
  definition; per-item `unstable-*` gates would add a second, weaker
  signaling mechanism with no additional mechanical enforcement.
- Instead, EXPERIMENTAL surface is controlled two ways, both enumerated in
  `API_SURFACE_AUDIT.md`:
  1. **Named feature gates** for opt-in subsystems — `vello`,
     `test-noop`, `platform`, `wayland`, `native-fallback`, `reactive`,
     `serde`, `devtools-timemachine`, `render`, `accesskit_android`,
     `windows-backend`, `macos-backend`, `wayland-backend`,
     `decoder`, `decoder-videotoolbox`, `decoder-mf`, `decoder-vaapi`,
     `decoder-ffmpeg` — items reachable only through these flags are
     tagged `feature …` in the generated audit where enumerable on the
     macOS doc host (items behind `decoder-ffmpeg`, `decoder-vaapi`,
     `windows-backend`, `wayland-backend`, and vello's `hot_reload` are
     not — see the caveats in `API_SURFACE_AUDIT.md` §1). `docs-rs` is
     deliberately absent from this list: it is docs.rs build metadata,
     not an API gate (see Non-feature-flags below).
  2. **Documented EXPERIMENTAL classification** for ungated items (e.g.,
     `martensite-wgpu::resilience`, `martensite-blessed::docking`,
     `martensite-plugin::runtime`), each with a stated rationale.
- **Post-1.0 convention** (recorded now so the freeze is mechanical): new
  incubating API added after v1.0.0 ships behind `unstable-*` feature
  flags; promoting an item to stable is a minor-release event that removes
  the gate. See `docs/DEPRECATION_POLICY.md` §3.

### Non-feature flags (build metadata, not API gates)

`docs-rs` features exist in `martensite`, `martensite-text`,
`martensite-window`, `martensite-access`, `martensite-access-platform`,
`martensite-clipboard-platform`, `martensite-media-platform`,
`martensite-font-fallback` for docs.rs builds only. The vendored crates
carry their own upstream flags out of freeze scope: `martensite-vello`
(`hot_reload`, `debug_layers`, `wgpu-profiler`, `bump_estimate`,
`wgpu_default`), `martensite-cosmic-text` (`no_std`, `vi`, `peniko`,
`shape-run-cache`, `monospace_fallback`, `warn_on_missing_glyphs`,
`wasm-web`, `fontconfig`, `std`), `martensite-accesskit-winit`
(`accesskit_unix`, `async-io`). `martensite-godot`'s `godot-gpu-copy`
flag is experimental upstream Godot API and the crate is
`publish = false` — outside the frozen surface entirely.

## 4. Semver Enforcement (`cargo-semver-checks`)

Mechanical enforcement is wired in `.github/workflows/ci.yml`
(`semver-checks` job):

- **Baseline:** the crates.io registry default — each crate is compared
  against its most recently published version (v0.17.0 at audit time).
- **Matrix:** all 30 non-vendored publishable crates, one parallel job
  each. Vendored forks are excluded because their surface tracks
  upstream and is re-synced rather than frozen (§5) — that rationale
  alone covers `martensite-accesskit-winit`, which uses
  `version.workspace = true`; only vello (0.10.0-martensite.1) and
  cosmic-text (0.19.0-martensite.1) carry `-martensite.N` versions off
  the workspace bump cadence.
- **Strictness:** advisory while `version == baseline` (mid-cycle 0.x
  development permits breaking changes); blocking once the manifest
  version is bumped past the baseline — i.e. on `release/*` PRs, tag
  pushes, and the `publish.yml` gate (`workflow_call`).
- **Coverage caveat:** the job passes `--default-features` explicitly —
  a bare `cargo semver-checks -p <crate>` applies an
  all-features-except-unstable heuristic that would pull in
  `decoder-ffmpeg`/`decoder-vaapi` and fail on missing libva/ffmpeg
  system packages. Feature-gated API remains outside the checked
  surface (documented inline in the job).

## 5. Vendored-Fork Maintenance Policy

The three vendored crates are EXPERIMENTAL-by-definition; their surface
tracks upstream and is re-synced, not frozen:

- `martensite-vello` — tracks `netrender-vello` 0.10 / Vello 0.10 on
  wgpu 30. Re-sync cadence: on wgpu major bumps or upstream security
  fixes. Local patches must be minimal and documented in the crate README.
- `martensite-cosmic-text` — tracks `cosmic-text` 0.19 on the same
  cadence rule.
- `martensite-accesskit-winit` — **temporary**: exit plan is removal once
  upstream `accesskit_winit` supports winit 0.31 (tracked in milestone
  v0.18.0 §4.5).

## 6. `#[non_exhaustive]` Usage

`#[non_exhaustive]` remains the mechanism for non-breaking additions to
public enums/structs; the v0.11.0-era per-crate counts (Appendix A) are
superseded by the machine enumeration in `API_SURFACE_AUDIT.md`.

## 7. Semver Policy Summary

- **0.x releases:** breaking changes allowed with minor bumps; EXPERIMENTAL
  surface may change in any release (see `DEPRECATION_POLICY.md` for the
  notice rules that still apply).
- **1.0.0+:** breaking changes require major bumps; stable-item removal
  requires completing the deprecation notice period in
  `DEPRECATION_POLICY.md`.
- **MSRV:** 1.89.0; bumps are minor-version events with 6-month changelog
  notice (`RELEASE_PROCESS.md` §6, `DEPRECATION_POLICY.md` §4).

## 8. Known API Friction (deferred to pre-RC)

The v0.18.0 dogfooding example (`examples/industrial_dashboard`) produced
a verified API-friction log (F1–F16, documented inline in that crate's
`main.rs`). The additive/non-breaking subset was fixed for v0.18.0:

- **F1** — `martensite::prelude` now re-exports `ReactiveRuntime`,
  `ReactiveError`, `Effect`, `create_signal`, `create_memo`,
  `create_effect`, `batch`, and `flush` alongside `Signal`/`Memo`.
- **F2** — `Theme`, `ThemeToken`, and `TokenKey` are in the prelude
  (previously only `Oklab`).
- **F3** — the facade now re-exports `martensite::blessed`,
  `martensite::shell`, and `martensite::devtools`, matching the other
  subsystem aliases.
- **F7** — `SplitDirection` rustdoc now states explicitly that the
  variant names the divider line's orientation (`Horizontal` → top/bottom
  children), not the child arrangement.
- **F9/F15** — `FocusManager::try_set_focus(arena, id) -> bool` reports
  whether focus actually moved; `set_focus` retains its `()` signature
  and its rustdoc now flags the silent no-op on missing
  `FOCUSABLE`/`VISIBLE` flags.
- **F10** — `KeyAction::from_key_name(key, shift, ctrl)` maps the
  framework's logical key names (winit `NamedKey` strings, as carried by
  `WidgetEvent::KeyPressed.key`) to table navigation actions with no new
  dependency edge.
- **F12** — `martensite_shell` re-exports `resolve_backdrop_material`
  and `resolve_vibrancy_material` at the crate root, matching its flat
  re-export convention.
- **F14** — `DataTable::sort_by` rustdoc now states the comparator always
  encodes *ascending* order and `Descending` reverses it.
- **F16** — `SelectionModel`/`extend_to` rustdoc now states that ranges
  are storage-index-based, so a reordered/filtered display can leave
  selected rows that are filtered out or non-contiguous on screen.

The following findings were **deferred to the pre-RC window** — they are
design decisions or breaking changes, not v0.18.0 blockers:

| ID  | Finding | Why deferred |
|-----|---------|--------------|
| F4  | `DockPanel::new` takes `u64`, not `WidgetId` | Signature change; `WidgetId` carries generation info and the right shape (typed id vs `Into<u64>`) needs a pre-RC decision to avoid ABA-prone `from_u64` bridges. |
| F5  | `martensite_core::Rect` (f32, origin/size) vs `martensite_blessed::Rect` (f64, x/y/w/h) | Unifying or renaming (`DockRect`?) is breaking; affects every docking consumer. |
| F6  | `ColumnConfig` has `set_*`/`&mut` API where siblings use builders | `with_*` builders are additive but churn the surface; bundled with the pre-RC ergonomics pass. |
| F8  | `LayoutEngine::compute` takes taffy `NodeId` while `register_node` is keyed by `WidgetId` | `compute_with_widgets` already covers the whole-pipeline case; a `compute_for_widget` convenience is additive but was kept out of the freeze batch. |
| F11 | `martensite::layout::Size` shadows `taffy::Size<T>` | Renaming geometry `Size` is breaking; re-exporting taffy's under a distinct name is a naming decision for pre-RC. |
| F13 | `StubBackdropController` has no inherent methods; `mode()` needs `BackdropController` in scope | The trait is already root-exported (now also `martensite::shell::BackdropController`); whether the stub gains inherent convenience methods is a pre-RC ergonomics decision. |

These items are recorded here so the pre-RC API review has a canonical
list; none of them block the v0.18.0 freeze.

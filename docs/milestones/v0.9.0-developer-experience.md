# Milestone Specification: v0.9.0 — Developer Experience

## 1. Executive Summary & Objectives
Milestone `v0.9.0` delivers the developer tooling, in-engine observability, and testing infrastructure for Martensite. It implements Tracy tracing spans, an in-app diagnostic HUD, a sub-350ms cdylib hot-reloading CLI (`cargo-martensite`), declarative component construction macros, and a deterministic headless CI harness.

---

## 2. Target Crates & Modules
- **`martensite-devtools`**:
  - `tracy`: Tracy profiler instrumentation across layout, paint, and reactive dispatch.
  - `hud`: In-app diagnostic overlay (frame time histogram, dirty rect visualizer, memory tracking).
- **`cargo-martensite`**:
  - `cli`: Command-line tool (`cargo martensite dev`, `cargo martensite build`).
  - `hot_reload`: Host executable and guest cdylib dynamic library reloader.
- **`martensite-macros`**:
  - `widget_macro`: Declarative `widget!` procedural macro with compile-time property validation.
- **`martensite-test`**:
  - `virtual_clock`: Fixed-step `VirtualClock` for deterministic animation and timer testing.
  - `harness`: Headless test harness with pixel-perfect perceptual snapshot diffing.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Sub-350ms Dynamic Hot-Reloading (`cargo-martensite`)
To enable rapid UI iteration without restarting application processes:
- The application architecture splits into a lightweight host binary and a guest dynamic library (`cdylib`).
- State preservation: The `WidgetArena` and reactive signal store reside in host-managed memory.
- When file changes occur, `cargo-martensite` re-compiles only the guest crate into a versioned `.dylib`/`.so`/`.dll`.
- The host pauses event polling, re-links the new dynamic library symbol table, updates component function pointers, and triggers a full layout re-measurement within $< 350	ext{ms}$.

### 4.2. In-App Performance Diagnostics HUD
Activating `F12` toggles a zero-allocation diagnostic overlay:
- Rolling 120-frame timing histogram displaying layout time, paint list encoding time, and GPU wait time.
- Real-time dirty rect visualization highlighting repainted screen regions in translucent green.
- Live `WidgetArena` slot utilization and compaction telemetry.

### 4.3. Deterministic Headless CI Testing Harness
To prevent non-deterministic CI failures caused by variable runner loads:
- `VirtualClock` replaces OS monotonic clocks during test execution.
- Tests advance time manually (`clock.advance(Duration::from_millis(16))`), driving animations, timers, and physics deterministically.
- Frames render to an offscreen buffer and compare against golden reference images using perceptual DSSIM thresholds.

---

## 5. Exit Criteria & Verification Gates
1. **Hot-Reload Latency Gate:**
   - Modifying a widget layout property in an example app recompiles, links, and refreshes the live window in $< 350	ext{ms}$.
2. **Deterministic CI Test Gate:**
   - 100 consecutive runs of the headless test suite on CI runners yield 100% identical pass results with zero timing jitter.
3. **DevTools Overhead Gate:**
   - Active Tracy profiling instrumentation contributes $< 0.1	ext{ms}$ overhead per 60fps frame.

---

## 6. Risk Matrix & Mitigations
| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| Dynamic library reload crashes on altered struct layouts | Medium | High | Strictly decouple component code from host arena state using stable ABI boundaries. |
| In-app HUD introduces rendering state contamination | Low | Medium | HUD renders in a dedicated render pass with isolated scissor rects. |

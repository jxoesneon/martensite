# Milestone Specification: v0.14.0 — External Surface Foundation

## 1. Executive Summary & Objectives

Milestone `v0.14.0` delivers the foundation for embedding external GPU
content inside Martensite's retained widget tree: a generic
external-texture widget (the `PaintCallback` primitive competitors already
ship — egui `CallbackTrait`, iced `widget::shader`, Slint
`Image::try_from(wgpu::Texture)`) and a new `martensite-engine-bridge`
crate defining the producer/consumer protocol.

This milestone was re-scoped during v0.13.0 post-release competitive
analysis. The original `INDEX.md` entry bundled Bevy/Godot integration,
zero-copy surfaces, and BT.2408 scaling into one milestone. Zero-copy
surface import and BT.2408-style tone mapping **already shipped in
v0.8.0** (`martensite-media`); the remaining work is split across four
milestones:

- **v0.14.0** (this spec): the generic external-surface primitive +
  bridge protocol (host-mode, same-device first).
- **v0.15.0**: Bevy and Godot adapters built on this foundation.
- **v0.16.0**: hardware decode pipeline + 4K120 gate.
- **v0.17.0**: widget breadth, web, mobile, time-travel debugging.

**Architecture decision (Direction A, confirmed):** Martensite remains the
application host — it owns the winit event loop, wgpu device, window,
accessibility tree, and compositing pass. External renderers produce
frames; Martensite consumes them. Martensite does *not* become a guest UI
inside Bevy/Godot render graphs. Recorded in ADR-0033.

The headline targets are:

- **Zero GPU copy on the same-device path** — the composite pass samples
  the producer's `wgpu::Texture` directly (fullscreen-triangle blit into
  the existing render pass), never via `queue.write_texture`, CPU
  readback, or Vello's `COPY_SRC` atlas path.
- **Correct damage integration** — a producer's `notify_frame_ready`
  marks the widget dirty and schedules a redraw without invalidating
  unrelated regions.
- **Graceful CPU-fallback degradation** — TinySkia renders the producer's
  optional `to_pixmap()` output or a documented placeholder; never a
  silent GPU→CPU readback of a streaming texture.

## 2. Target Crates & Modules

- **`martensite-engine-bridge`** (NEW, `#![forbid(unsafe_code)]`):
  - `engine`: `Engine` producer trait, `EngineContext` (shared
    `wgpu::Device`/`Queue` access), `Viewport` descriptor.
  - `frame`: `Frame` trait, `FrameToken`, `FrameSync` enum,
    `SourceAlpha`, `NativeFrame` platform-handle descriptors
    (stubs for v0.15.0+).
  - `bridge`: `BridgeHandle` / `SurfaceId` registration,
    `notify_frame_ready` damage signaling, two-slot frame ring,
    `release` recycling.
- **`martensite-wgpu`**:
  - `external`: `WgpuHost` composite pipeline — fullscreen-triangle
    sampler with straight/premultiplied-alpha pipeline variants,
    bind-group cache, per-surface entry table. Direct `TextureView`
    sampling modeled on `netrender::ExternalTextureComposite`.
  - `interop`: reuse `create_video_texture_view` and extend for general
    `Rgba8Unorm`/`Bgra8Unorm` external textures (video path unchanged).
- **`martensite`**:
  - `widgets/external.rs` (NEW): `ExternalEngine` widget — Taffy
    replaced-element leaf that emits `PaintCommand::External` and
    forwards layout `bounds`/`clip`/`scale_factor` to the bridge.
- **`martensite-render`**:
  - `PaintCommand::External { surface_id, bounds, clip }` variant.
  - TinySkia backend: rasterize `Engine::to_pixmap()` result or
    placeholder.
- **`martensite-test`**:
  - `MockEngine` producer generating deterministic synthetic frames for
    headless verification — shipped in
    `martensite-engine-bridge::testing` (better dep direction; the test
    crate stays GUI-free).
- **Example app**: `examples/engine_embed` — a winit window driving
  `MockEngine` → `ExternalEngines::drive_frame` → `ExternalEngine` →
  `RenderOrchestrator` → present end to end.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Bridge Protocol (`martensite-engine-bridge`)

```rust
/// Per-frame token passed from the external engine to the host.
pub struct FrameToken(pub u64);

/// How the host must wait before sampling this frame.
pub enum FrameSync {
    /// Same-device, same-queue: ordering via Queue::submit is sufficient.
    None,
    /// D3D12 shared fence value (Windows).
    FenceValue(u64),
    /// Vulkan timeline semaphore fd (Linux dma-buf path).
    VkSemaphoreFd { fd: i32, value: Option<u64> },
    /// Metal shared event (macOS/iOS).
    MetalSharedEvent(u64),
    /// DXGI keyed mutex (Windows legacy cross-process).
    DxgiKeyedMutex { key: u64 },
}

/// Alpha interpretation of the produced frame.
pub enum SourceAlpha {
    Straight,
    Premultiplied,
}

/// A frame produced by an external engine.
pub trait Frame: Send + Sync {
    fn token(&self) -> FrameToken;
    /// Same-device wgpu texture (the v0.14.0 primary path).
    fn same_device_texture(&self) -> Option<&wgpu::Texture>;
    /// Imported native handle (v0.15.0+ cross-device path).
    fn native_handle(&self) -> Option<NativeFrame>;
    fn sync(&self) -> FrameSync;
    fn size(&self) -> (u32, u32);
    fn alpha_mode(&self) -> SourceAlpha;
}

/// Implemented by Bevy, a video decoder, a web compositor, etc.
pub trait Engine: Send + Sync {
    fn render(&mut self, ctx: &mut EngineContext, viewport: Viewport)
        -> Option<Box<dyn Frame>>;
    /// Host finished compositing this token; the texture may be recycled.
    fn release(&mut self, token: FrameToken);
    /// Optional CPU copy for the TinySkia fallback path.
    fn to_pixmap(&self, token: FrameToken) -> Option<CpuFrame> { None }
}
```

`NativeFrame` descriptors (`DmaBuf`, `IoSurface`,
`SharedHandle`) are declared but the import path is exercised in
v0.15.0; v0.14.0 verifies `same_device_texture` end-to-end.

### 4.2. Same-Device Composite Pipeline (`martensite-wgpu::external`)

`WgpuHost` owns the consumer side:

- Two render pipelines (straight vs premultiplied source alpha), a
  6-vertex fullscreen-triangle draw, `source_view` sampled at
  screen-space UVs — the `netrender::ExternalTextureComposite` pattern.
- Per-`SurfaceId` entry: `texture`, `view`, `sampler`, `alpha`, `size`,
  `ready_token`, and a two-slot ring (acquired/ready) so the producer
  never writes the texture the host is sampling.
- `composite(surface_id, &mut RenderPass, bounds, clip)` — sets viewport
  to the widget's physical bounds and scissor to the clip rect, matching
  egui's `PaintCallbackInfo` (`viewport_in_pixels`/`clip_rect_in_pixels`)
  and iced's `Primitive::render` contract.

**Deliberately not used:** Vello `Renderer::register_texture` /
`override_image`. They require `COPY_SRC` and copy into Vello's image
atlas every frame — a per-frame GPU copy this milestone exists to
eliminate.

### 4.3. `ExternalEngine` Widget

- Taffy **replaced-element leaf**: `MeasureFunction` returns the frame's
  intrinsic size for `auto` dimensions, honors `aspect-ratio` and
  min/max constraints.
- `paint` emits `PaintCommand::External { surface_id, bounds, clip }`.
- Layout invalidation: a frame size change calls `request_layout`; a
  same-size new frame calls `request_redraw` only.

### 4.4. Damage & Frame Pacing

- `BridgeHandle::notify_frame_ready(token)` sets the widget dirty flag
  and calls `window.request_redraw()`. The external region's `bounds`
  join the frame's damage set.
- Presentation pacing: `Window::pre_present_notify()` before
  `queue.present()`; `PresentMode::Fifo` default (`Mailbox` opt-in for
  streaming producers).
- Producers are redrawn *on demand* (frame-ready → redraw), not polled
  every `about_to_wait` — preserves event-driven idle behavior.

### 4.5. Synchronization

**v0.14.0 — same device, same queue (primary path):**
1. Producer `queue.submit`s its frame commands.
2. Host `queue.submit`s the composite pass.
3. Same-queue serial ordering guarantees visibility — no semaphores.
4. Async producers use `queue.on_submitted_work_done` before
   `notify_frame_ready`.

**Declared for v0.15.0+ — cross-device:** `FrameSync` variants map to
`Queue::add_wait_semaphore` (Vulkan), `add_wait_fence` (DX12),
`add_wait_event` (Metal); `add_signal_*` + `Engine::release` for
producer-side recycling.

### 4.6. CPU Fallback (TinySkia)

- `Engine::to_pixmap(token)` returns an optional `tiny_skia::Pixmap`;
  TinySkia composites it via `draw_pixmap`.
- If the producer provides no pixmap, TinySkia renders a documented
  placeholder (checkerboard + "GPU content unavailable" glyph block).
- **Forbidden:** silent `wgpu` → CPU readback of streaming textures.

## 5. Exit Criteria & Verification Gates

| Gate | Criterion | Verification |
|------|-----------|--------------|
| Same-device zero-copy | `MockEngine` texture composited without `write_texture`/readback/`COPY_SRC` atlas path | `composite_front_*` noop tests + code path inspection (no copy APIs in the composite path) |
| Damage integration & pacing | Ready events → `ExternalEngines::drain_ready` → surface list for the app's dirty/redraw call | `drain_ready_*` unit tests; `examples/engine_embed` end-to-end — `drive_frame` → ready events → `request_redraw` → `pre_present_notify` → present |
| Two-slot ring | No torn frames: host takes front under the registry lock, releases after `queue.submit` | `composite_front_takes_and_composites_ring_frame` + mailbox unit tests |
| Layout contract | Replaced-element sizing, aspect-ratio, resize → texture renegotiation | `measure_*`/`contain_fit_*`/`layout_forwards_viewport_to_bridge` unit tests |
| CPU fallback | `to_pixmap` → `CpuFrame` composited via `composite_rgba_frame`; missing pixmap → placeholder | `composite_rgba_frame_*` unit tests |
| Release lifecycle | `Engine::release` called exactly once per composited token | `release_fires_exactly_once_per_composited_token` + `external_engines_drives_release_lifecycle` |
| All gates | fmt, clippy (default + all-features), tests, doctests, docs, audit, deny, vet, benchmarks | Full CI suite |

  is **not** usable without a bump.

## 7. Unsafe Code Policy

`martensite-engine-bridge` is `#![forbid(unsafe_code)]`. The v0.14.0
same-device path needs no unsafe code — `wgpu::Texture` sharing within
one device is fully safe. The v0.15.0+ `NativeFrame` import paths
(`create_texture_from_hal`, `texture_from_dmabuf_fd`) will live in the
existing allowed-unsafe `martensite-media-platform` / a future
`martensite-bridge-platform` crate, consistent with the workspace's
unsafe-isolation convention.

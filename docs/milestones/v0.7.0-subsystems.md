# Milestone Specification: v0.7.0 — Advanced Subsystems

## 1. Executive Summary & Objectives
Milestone `v0.7.0` delivers essential application subsystems: transactional state undo/redo using a Lowest Common Ancestor (LCA) tree algorithm, a dual-mode Virtual File System (VFS) for static assets, and dynamic internationalization with Project Fluent.

---

## 2. Target Crates & Modules
- **`martensite-history`**:
  - `ledger`: Transactional state ledger, atomic change records, bounded depth history.
  - `lca`: Lowest Common Ancestor tree navigation for branching history graphs.
- **`martensite-assets`**:
  - `vfs`: Dual-mode VFS (`VfsBackend::Disk` for live hot-reloading in debug, `VfsBackend::Embedded` for zero-copy memory bundles in release).
  - `shader`: Ahead-of-Time (AOT) WGSL shader validation and naga reflection.

> **Implementation Note (v0.10.0):** The original spec called for `spirv-cross`
> reflection. Martensite uses `naga` instead because it provides equivalent
> reflection capabilities (entry points, workgroup sizes, resource bindings)
> as a pure-Rust crate, avoiding the C++ build dependency that `spirv-cross`
> requires. This simplifies cross-compilation and CI without losing any
> reflection information needed for pipeline-layout creation. See the
> `martensite_assets::shader` module documentation for details.
- **`martensite-l10n`**:
  - `fluent`: Project Fluent bundle integration, localization string maps.
  - `direction`: Script directionality resolution (LTR/RTL).

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Lowest Common Ancestor (LCA) Tree History Ledger
To support non-linear undo/redo (e.g. branching history trees where users undo, make an edit, and later jump back to an abandoned branch):
- History nodes form a directed tree with parent pointers.
- Jumping from current node $C$ to target node $T$ executes via the LCA algorithm:
  1. Ascend from $C$ and $T$ to find the lowest common ancestor node $A$.
  2. Revert state deltas in reverse along the path $C 	o A$.
  3. Apply state deltas forward along the path $A 	o T$.
- Bounded depth: When total ledger entries exceed the configured limit (e.g. 500 actions), the oldest leaf nodes or root nodes prune without breaking active tree branches.

### 4.2. Dual-Mode Asset VFS
Asset loading operates transparently across development and release configurations:
- **Development Mode (`VfsBackend::Disk`):** Resolves asset paths directly from the workspace filesystem, watching for changes on a background thread and emitting invalidation signals on file modifications.
- **Release Mode (`VfsBackend::Embedded`):** Assets compile directly into the binary using zero-copy memory slices (`include_bytes!`), achieving sub-microsecond resolution latency.

### 4.3. Dynamic Localization Without Tree Rebuilding
Project Fluent integration (`martensite-l10n`) binds translated string resources directly into the reactive signal graph:
- A locale switch (`l10n.set_locale("es-ES")`) updates the root locale signal.
- Only text leaf nodes bound to localized strings invalidate their dirty bitmasks; the structural layout hierarchy remains undisturbed.

## 5. Exit Criteria & Verification Gates
1. **LCA History Integrity Gate:**
   - 10,000 randomized state rollbacks and branch transitions restore exact bit-level state.
2. **Asset Resolution Performance:**
   - Embedded VFS resolves asset data pointers in $< 10\mu	ext{s}$.
3. **Locale Switch Gate:**
   - Switching application locale across 1,000 active text nodes settles within 1 frame.

## 6. Risk Matrix & Mitigations
| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| Large asset memory footprint in embedded mode | Medium | Medium | Implement optional LZ4 asset block compression in embedded binary bundles. |
| Memory leakage in unbounded undo trees | Medium | High | Strict LRU pruning of unreferenced history branches. |

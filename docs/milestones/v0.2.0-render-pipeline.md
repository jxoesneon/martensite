# Milestone Specification: v0.2.0 — The Rendering Pipeline

## 1. Executive Summary & Objectives
Milestone `v0.2.0` establishes the GPU compute rendering pipeline, hardware swapchain integration, and window event pump for Martensite. It introduces Vello-driven compute path rasterization over WGPU, an automatic CPU rasterization fallback via TinySkia, and a robust GPU device loss recovery state machine guaranteeing restoration in under 16.6 milliseconds.

---

## 2. Target Crates & Modules
- **`martensite-wgpu`**:
  - `device`: `GpuContext`, adapter enumeration, feature selection, device/queue lifecycle.
  - `surface`: Swapchain configuration, present mode negotiation, resize re-creation.
  - `resilience`: 5-state GPU recovery FSM, exponential backoff, device loss simulation harness.
- **`martensite-render`**:
  - `paint`: `PaintList`, draw command stream encoding, path builders, gradient definitions.
  - `vello_backend`: `VelloRenderer`, scene composition, fine-raster dispatch.
  - `tinyskia_backend`: CPU software rasterizer, pixel buffer transfer.
  - `diff`: Perceptual diffing engine (DSSIM with grayscale edge masking).
- **`martensite-window`**:
  - `manager`: `WindowManager`, multi-window winit event loop integration.
  - `dpi`: Physical-to-logical coordinate scaling, dynamic monitor DPI change handling.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. GPU Device Loss Recovery FSM
To survive driver crashes, external display disconnects, and GPU timeout detection recovery (TDR) without terminating the host process, the rendering context implements a formal typestate recovery machine:

```mermaid
stateDiagram-v2
    [*] --> Active
    Active --> DeviceLost : SurfaceError::Lost / DeviceRemoved
    DeviceLost --> SuspendedWithRetry : Drop Swapchain & Pipelines
    SuspendedWithRetry --> Recreated : Enumerate Adapter & Request Device
    SuspendedWithRetry --> FallbackCpu : Retry Exceeded (>32ms)
    Recreated --> Restored : Rebuild Vello Pipelines & Rebind Textures
    Restored --> Active : Repaint Next Frame (<16.6ms)
    FallbackCpu --> Active : Software Fallback Active
```

```rust
pub enum DeviceStatus {
    Active,
    DeviceLost { error: wgpu::SurfaceError, timestamp: std::time::Instant },
    SuspendedWithRetry { attempts: u32, next_retry: std::time::Instant },
    Recreated,
    Restored,
}
```

### 4.2. PaintList Command Stream & Scene Translation
Rendering operations are decoupled from widget layout through the `PaintList` linear command buffer. Widgets write draw primitives into `PaintList` without allocating intermediate heap objects:
- Clip rectangles and rounded clips.
- Filled and stroked Bézier paths.
- Linear and radial color gradients.
- Solid color fills and border strokes.
- Glyph run instances with pre-resolved coordinates.

The `VelloRenderer` translates `PaintList` into a Vello `Scene` per frame, dispatching compute shaders to calculate fine-raster geometry.

### 4.3. TinySkia CPU Software Fallback
For environments where GPU compute shaders are unavailable or when explicit software rendering is selected:
- Martensite provides `TinySkiaBackend`, rendering draw primitives into an RGBA CPU pixel buffer.
- Presentation uploads the CPU pixel buffer to a software window frame buffer (`softbuffer`) or blits through a minimal swapchain texture.
- An explicit application configuration flag (`App::build().allow_software_fallback(true)`) acknowledges the performance trade-off in headless or restricted CI environments.

### 4.4. Perceptual Diffing & Grayscale Edge Masking
Because Vello uses GPU compute fine-rasterization and TinySkia uses CPU scanline rasterization, subpixel anti-aliasing profiles differ at path boundaries. The CI regression harness implements DSSIM with grayscale edge masking:
- Pixels along high-frequency luminance gradients are tested with an expanded structural similarity tolerance ($SSIM \ge 0.995$).
- Fill interiors and layout bounding rects are verified with strict absolute matching ($SSIM \ge 0.9999$).

## 5. Exit Criteria & Verification Gates
1. **Visible Triangle & Geometry Test:** Interactive application window successfully opens and renders solid rectangles, rounded borders, and anti-aliased circles at 60fps/120fps.
2. **Device Loss Recovery Gate:**
   - Injected device loss (`wgpu::Device::destroy` or simulated driver reset) triggers recovery and repaints the active scene in $< 16.6	ext{ms}$.
3. **Software Fallback Parity Gate:**
   - TinySkia backend passes golden frame comparisons with $\ge 99.9\%$ DSSIM across all standard test primitives.
4. **Zero-Allocation Hot Loop:**
   - Translating and presenting an unchanged scene generates 0 heap allocations per frame.

## 6. Risk Matrix & Mitigations
| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| Driver TDR takes >100ms to re-enumerate adapter | Low | High | Immediate transition to TinySkia CPU fallback while background thread polls adapter recreation. |
| Modal window resize loops cause presentation stalls | Medium | Medium | Non-blocking surface acquisition with `wgpu::Maintain::Poll`. |

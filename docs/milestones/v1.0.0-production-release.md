# Milestone Specification: v1.0.0 — Production Stability

## 1. Executive Summary & Objectives

Milestone `v1.0.0` represents the production-ready, stabilized release of the
Martensite GUI framework. It establishes a formal API freeze under Semantic
Versioning 2.0, complete documentation coverage across all public interfaces,
comprehensive security verification, and general availability on crates.io.

**Release sequence.** v1.0.0 is shipped through a release-candidate line:
`v0.18.0` (Production Hardening & Dogfooding) → `v0.19.0` (Distribution)
→ `v1.0.0-rc.N` (soak) → `v1.0.0`. The RC tags run the full gated publish
pipeline so that the release machinery itself is exercised before the stable
tag. No new API surface may land between `v1.0.0-rc.1` and `v1.0.0` except
bug fixes that do not change the frozen API.

This document is the single definition of v1.0.0 scope. Items that earlier
planning documents attached to "v1.0.0" have been explicitly assigned:

| Earlier source | Item | Assigned to |
| :--- | :--- | :--- |
| `PROJECT.md` Phase 18 | Criterion benchmark suite vs egui/iced baselines | v0.18.0 |
| `PROJECT.md` Phase 18 | Industrial dashboard (full workstation demo) | v0.18.0 |
| `INDEX.md` diagram | WiX / DMG / Flatpak installers | v0.19.0 |
| `INDEX.md` diagram | Ed25519 signed updates | v0.19.0 |
| This document §4.1–4.3 | API freeze, docs coverage, security audit | v0.18.0 work, v1.0.0 gate |
| This document §4.4 | Governance transition | Post-1.0 evaluation only |

## 3. Entry Criteria

- `v0.18.0` and `v0.19.0` released (or `v0.19.0` formally descoped by ADR).
- `v1.0.0-rc.N` published through the full gated pipeline with zero
  gate failures and soaked for a minimum of two weeks.
- Every environment-gated verification leg has either **executed on real
  hardware/runners** or been **formally descoped** in `WORKING_ON.md` and
  `docs/PLATFORM_SUPPORT.md` with its claim downgraded (e.g. "compile-verified"
  instead of "supported"). No silently-deferred gates.
- Zero open critical architectural issues or unaddressed review findings.
- `cargo-semver-checks` clean between the last `0.x` release and the RC.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Public API Stabilization & SemVer 2.0 Freeze

- All public types, traits, methods, and error enums are stabilized.
- Strict adherence to Semantic Versioning 2.0:
  - No breaking changes allowed within the `1.x.y` version cycle.
  - Experimental features gated strictly behind explicit feature flags
    (`unstable-*`); the flag inventory is finalized in v0.18.0.
- Public APIs enforce `#![deny(missing_docs)]` and `#![deny(unsafe_code)]`
  across all library crates (the ten audited FFI/vendored exceptions listed
  in `AGENTS.md` are the complete set).
- `cargo-semver-checks` runs in CI on every release PR and on the RC tag;
  the freeze is enforced mechanically, not by convention.

### 4.2. Complete Documentation Coverage

- 100% of public items documented with doc comments explaining purpose,
  parameters, return values, and failure modes (enforced by
  `missing_docs = "deny"` plus a docs-quality review pass).
- Executable doctests provided for all primary builder methods and widget
  modifiers (vendored forks `martensite-cosmic-text` and `martensite-vello`
  exempt per `AGENTS.md`).
- End-to-end tutorial documentation (delivered in v0.18.0) covering:
  - Project initialization with `cargo-martensite`.
  - Core reactive state management.
  - Custom widget implementation following the two-pass layout contract.
  - Accessibility validation.
- `docs/MIGRATION_GUIDE_0x_to_1x.md` finalized against the frozen API.
- `docs/PLATFORM_SUPPORT.md` accurately reflects verified-vs-compile-verified
  status for every tier.

### 4.3. Security Audit & Supply Chain Verification

- Complete audit of workspace dependency tree using `cargo audit`,
  `cargo vet`, and `cargo deny check` — all green on the RC commit.
- Verification of zero known CVEs in all direct and transitive dependencies.
- Reproducible build verification across Linux, macOS, and Windows CI
  runners (delivered in v0.18.0, re-verified on the RC tag).

### 4.4. Governance

- The foundation-transition aspiration from earlier planning is reduced to
  a documented evaluation: upon v1.0.0 publication, maintainers *begin
  evaluating* independent-stewardship options. It is not a release
  deliverable and does not gate the tag.

## 5. Exit Criteria & Verification Gates

1. **Compilation & Warning Gate:**
   - `cargo check --workspace` exits with zero errors.
   - `cargo clippy --workspace --all-targets -- -D warnings` and
     `--all-features` exit with zero warnings.
   - Zero occurrences of `todo!()` or `unimplemented!()` in any shipping
     crate's non-doc code (vendored `martensite-vello` stubs resolved or
     replaced with real error paths in v0.18.0).
2. **Test Suite Gate:**
   - 100% test pass across unit, integration, and doc tests under both
     default and all-feature builds.
   - All `target-checks` matrix legs (wasm32, ios-sim, android) green.
3. **Security Audit Gate:**
   - `cargo audit`, `cargo deny check`, and `cargo vet --locked` all clean.
4. **SemVer Gate:**
   - `cargo-semver-checks` reports no breaking changes between `v0.19.0`
     (or the last `0.x` release) and the RC.
5. **Release Gate:**
   - Workspace packages publish to crates.io via the gated `publish.yml`
     pipeline on the `v1.0.0` tag.
   - GitHub Release created with complete changelog-derived notes and
     pre-built `cargo-martensite` CLI binaries (delivered in v0.19.0).
   - Installer artifacts (WiX/DMG/Flatpak) published per v0.19.0 scope, if
     that milestone is retained.

## 6. Risk Matrix & Mitigations

| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| Breaking API change discovered immediately post-launch | Medium | High | RC soak period + `cargo-semver-checks` gate + real-application dogfooding in v0.18.0. |
| Freezing APIs never exercised by real consumers | High | High | Industrial-dashboard workstation demo and tutorial-driven usage in v0.18.0 before the freeze. |
| Platform claims outrun verification (compile-only platforms shipped as "supported") | Medium | Medium | Platform-tier honesty pass in v0.18.0; env-gated legs run or formally descoped before RC. |
| `winit 0.31` still beta at freeze time | Medium | Medium | Track upstream to stable in v0.18.0; vendored `accesskit-winit` removal plan documented. |
| Documentation build failure on docs.rs | Low | Medium | `cargo doc --all-features --no-deps` validated locally and in CI prior to publication. |
| Installer/update scope slips | Medium | Low | v0.19.0 may be descoped to post-1.0 by ADR without blocking the RC. |

# Milestone Specification: v0.8.0 — Media & Advanced GPU

## 1. Executive Summary & Objectives
Milestone `v0.8.0` integrates hardware video decoders and HDR color science into the Martensite graphics pipeline. It implements zero-copy surface passthrough for NV12 (8-bit SDR) and P010 (10-bit HDR) hardware video frames, provides custom WGSL compute EOTF shaders, and establishes display-adaptive SDR reference white scaling to prevent highlight crushing on budget displays.

---

## 2. Target Crates & Modules
- **`martensite-media`**:
  - `surface`: Zero-copy hardware surface binding (DXGI NT handles, macOS IOSurface, Linux dma-buf).
  - `color`: BT.709 and BT.2020 color space definitions, PQ (SMPTE ST 2084) EOTF compute pipeline.
  - `tonemap`: Display-adaptive luminance tone-mapping (Hable/Uchimura filmic operators).
- **`martensite-wgpu`**:
  - `interop`: External memory import extensions, texture format negotiation.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Zero-Copy Video Surface Passthrough
Traditional video display pipelines copy frames from GPU decoder memory to CPU RAM, then re-upload them to GPU textures. Martensite bypasses the CPU entirely:
- **Windows:** Import DXGI shared NT handles directly into `wgpu::Texture` via Direct3D 12 interop.
- **macOS:** Wrap `IOSurfaceRef` into Metal `MTLTexture`.
- **Linux:** Import Vulkan `dma-buf` file descriptors via `VK_EXT_external_memory_dma_buf`.
- Result: 4K 60fps video frames render with approximately 0.0ms CPU dispatch overhead.

### 4.2. P010 (10-Bit HDR) BT.2020 PQ EOTF WGSL Pipeline

### 4.3. Display-Adaptive Reference White Scaling
Compositing SDR UI controls over 10-bit HDR video requires careful optical luminance alignment:
- Instead of assuming a static 203-nit reference white, Martensite dynamically queries display capabilities:
  ```rust
  let ref_white = display.sdr_white_level_nits().unwrap_or(203.0).min(display.max_luminance_nits());
  ```
- On low-nit SDR screens (e.g. budget laptops with 150-180 nits peak brightness), SDR UI elements are scaled to match the physical panel headroom, preventing gradient clipping or washed-out controls.
- UI overlay widgets blend in linear optical space (scRGB) using pre-multiplied alpha.

## 5. Exit Criteria & Verification Gates
1. **Zero-Copy Video Playback Gate:**
   - 4K 60fps NV12 and P010 video playback runs inside the widget hierarchy with $< 1\%$ CPU utilization.
2. **Colorimetric Accuracy:**
   - Colorimetric test patterns confirm $\Delta E < 1.0$ against reference color bars.
3. **HDR/SDR Blending Verification:**
   - UI controls composited over HDR video surfaces maintain standard contrast ratios without luminance clipping.

## 6. Risk Matrix & Mitigations
| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| Platform external memory extensions unsupported on legacy drivers | Low | High | Fall back to CPU copy pipeline with explicit telemetry warning. |
| HDR swapchain unavailable on display hot-plug | Medium | Medium | Automatic fallback to filmic SDR tone mapping (Hable operator). |

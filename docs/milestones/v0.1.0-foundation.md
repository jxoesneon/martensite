# Milestone Specification: v0.1.0 — The Foundation

## 1. Executive Summary & Objectives
Milestone `v0.1.0` establishes the deterministic core memory model, generational slotmap arena, and reactive signal scheduler for the Martensite GUI framework. It delivers the structural baseline upon which all layout, rendering, and event routing systems operate, guaranteeing zero garbage collection and predictable cache line locality.

- **`martensite-core`**:
  - `arena`: `WidgetArena`, generational indexing, dense-sparse mapping, FIFO free-list, memory compaction.

  - `memo`: `Memo<T>`, pure synchronous derived evaluations.
  - `scheduler`: Push-pull two-phase scheduler, topological rank queue, dirty bitset tracking.
  - `cycle`: 3-color DFS active-path cycle detection and circuit breaker.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. HotNode Memory Layout & Invariant
`HotNode` is the performance-critical data structure traversed during hit-testing, layout, and rendering passes. To prevent false sharing and ensure exact single-cache-line utilization on 64-bit platforms, `HotNode` is packed into exactly 64 bytes:

```rust
#[repr(C, align(64))]
pub struct HotNode {
    pub bounds: Rect,                    // 16 bytes (min position + size via glam::Vec2)
    pub layout_id: taffy::NodeId,        // 8 bytes  (Taffy layout node reference)
    pub flags: NodeFlags,                // 4 bytes  (dirty, visible, focused, etc.)
    pub depth_rank: u16,                 // 2 bytes  (Topological tree depth)
    pub z_index: i16,                    // 2 bytes  (Local stacking order)
    pub parent: Option<WidgetId>,        // 8 bytes  (NonZeroU64 niche optimization)
    pub first_child: Option<WidgetId>,   // 8 bytes
    pub next_sibling: Option<WidgetId>,  // 8 bytes
    pub prev_sibling: Option<WidgetId>,  // 8 bytes
}

const _: () = assert!(std::mem::size_of::<HotNode>() == 64);
const _: () = assert!(std::mem::align_of::<HotNode>() == 64);
```

### 4.2. Generational Rollover Immunity (Strict FIFO Free-List)
To prevent rapid generational wrapping under synthetic or bursty widget creation and destruction patterns:
1. The free-list uses a FIFO queue (`VecDeque<u32>`) rather than a LIFO stack.
2. Free slot recycling distributes generation increments evenly across all $N$ allocated slots, extending the wrap-around threshold to months under continuous synthetic load.
3. Generation increments explicitly skip zero. Uninitialized or zeroed pages (from OS `madvise(MADV_FREE_REUSABLE)` or `VirtualAlloc(MEM_RESET)`) evaluate as invalid `WidgetId` handles.

```rust
#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct WidgetId(std::num::NonZeroU64);

impl WidgetId {
    pub const fn new(slot_index: u32, generation: u32) -> Option<Self> {
        if generation == 0 {
            return None;
        }
        let raw = ((generation as u64) << 32) | (slot_index as u64);
        std::num::NonZeroU64::new(raw).map(WidgetId)
    }

    pub const fn slot_idx(self) -> u32 {
        self.0.get() as u32
    }

    pub const fn generation(self) -> u32 {
        (self.0.get() >> 32) as u32
    }

    pub const fn to_le_bytes(self) -> [u8; 8] {
        self.0.get().to_le_bytes()
    }
}
```

### 4.3. Arena Compaction Protocol
The arena maintains a dense contiguous array of `HotNode` elements alongside a sparse slot-mapping table. Compaction executes via a 5-step protocol:
1. Identify target sparse slot to relocate from the end of the dense array.
2. Execute `swap_remove` on the dense array to fill the deleted slot.
3. Update the relocated element's sparse slot entry to point to its new dense index.
4. Update the reverse-mapping table entry.
5. Invalidate the removed slot's generation counter.

### 4.4. Reactive DAG Two-Phase Scheduler & 3-Color Cycle Detection
The reactive signal scheduler executes in two distinct phases:
- **Phase 1 (Push / Mark):** Breadth-first dirty bitset propagation using pre-computed topological depth ranks. No subscriber computations are executed during Phase 1.
- **Phase 2 (Pull / Evaluate):** Priority-queue evaluation sorted strictly by ascending topological depth rank. This guarantees diamond dependencies (`A -> B, C -> D(B, C)`) evaluate `D` only once, after both `B` and `C` are current.
- **Dynamic Dependency Pruning:** Epoch tracking (`eval_epoch`) unlinks stale subscriptions dynamically when conditional branches change (`if cond { a.get() } else { b.get() }`).
- **3-Color DFS Cycle Breaker:** During graph traversal, nodes are colored `White` (unvisited), `Gray` (active on stack), or `Black` (fully resolved). If a traversal encounters a `Gray` node, a cyclic dependency is confirmed; the scheduler records an error, marks the node as poisoned, and isolates the cycle without deadlocking.

## 6. Risk Matrix & Mitigations
| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| Dynamic edge additions trigger lock convoying | Medium | High | Thread-local evaluation journals; read-only signal snapshots via double-buffering. |
| Memory fragmentation from large node churn | Low | Medium | Background idle compaction and periodic virtual memory reset via platform page advice APIs. |

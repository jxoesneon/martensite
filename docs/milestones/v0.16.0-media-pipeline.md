# Milestone Specification: v0.16.0 — Hardware Media Pipeline

## 1. Executive Summary & Objectives

Milestone `v0.16.0` completes the media stack promised in v0.8.0. The
zero-copy *import* half already ships (`martensite-media-platform` maps
IOSurface/DXGI/dma-buf into `wgpu::Texture`; `VideoProcessor` does
in-VRAM YUV→RGB + PQ/scRGB + tonemap). What's missing is the *producer*:
a hardware video decoder that outputs those handles, plus the
multi-plane import fix and a real 4K120 end-to-end gate.

The headline targets:

- **4K 120fps playback with <0.1% frame drops** — a dropped frame is one
  whose PTS deadline passes unsubmitted, or that is skipped because the
  pipeline is >1.5 frame-intervals behind. Measured by `FrameQueue`
  accounting, gated on a dedicated GPU runner.
- **<1% CPU dispatch utilization** at 4K60 — extends the existing
  `VideoSurface::cpu_utilization_pct` telemetry to the decode path.
- **Every decode→display hop is zero-copy on hardware backends** —
  decoder → platform surface handle → wgpu texture → `VideoProcessor`
  → composite. Software fallback (`ffmpeg-next` → `import_cpu_memory`)
  exists but is not the gated path.

## 2. Target Crates & Modules

- **`martensite-media`** (`#![forbid(unsafe_code)]`):
  - `decoder` (NEW): `VideoDecoder` trait, `DecoderConfig`,
    `EncodedPacket`, `DecodedFrame`, `DecodeStats`, `MockDecoder`.
  - `hdr` (NEW): `HdrMetadata` (EOTF, color space, mastering-display
    volume, content-light-level, optional HDR10+ dynamic metadata) →
    `VideoPipelineUniforms` population.
  - `queue` (NEW): `FrameQueue` — decode-ahead ring (2–3 frames), PTS
    deadline skip policy, `drop_rate_pct`, `presented`/`dropped`
    counters.
- **`martensite-media-platform`** (allowed-unsafe FFI crate):
  - `decoder/macos.rs`: `objc2-video-toolbox` `VTDecompressionSession`
    → `CVPixelBuffer` (IOSurface-backed via
    `kCVPixelBufferIOSurfacePropertiesKey`) → `HardwareHandle::IoSurface`.
  - `decoder/windows.rs`: Media Foundation `IMFSourceReader` +
    `IMFDXGIDeviceManager` → `IMFDXGIBuffer` → `ID3D11Texture2D` →
    `CreateSharedHandle` → `HardwareHandle::Dxgi`.
  - `decoder/linux.rs`: `cros-libva` decode → `vaExportSurfaceHandle`
    (`VADRMPRIMESurfaceDescriptor`) → `HardwareHandle::DmaBuf`.
  - `decoder/ffmpeg.rs`: `ffmpeg-next` software fallback →
    `HardwareHandle::CpuMemory`.
  - Fix `ImportTextureDescriptor`: add `plane_index`; import NV12/P010
    as **two** textures (Y + UV) — `import_iosurface` currently
    hard-codes plane 0; `import_dxgi_texture` and `import_dmabuf` are
    stubs to implement.
- **`martensite-wgpu`**:
  - `interop.rs`: `VideoProcessor` unchanged in shape; consumes paired
    Y/UV views; `VideoPipelineUniforms` gains fields populated from
    `HdrMetadata`.
- **`martensite`**: `widgets/media.rs` — wire the media widget to
  `VideoDecoder` + `FrameQueue` (it currently exists without a decode
  producer).
- **`martensite-media-test`**: mock-decoder conformance suite; noop-wgpu
  pipeline tests.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Decoder Trait (safe, `martensite-media`)

```rust
pub trait VideoDecoder: Send {
    fn init(config: DecoderConfig) -> Result<Self, MediaError> where Self: Sized;
    fn send_packet(&mut self, packet: &EncodedPacket) -> Result<(), MediaError>;
    fn try_recv_frame(&mut self) -> Result<Option<DecodedFrame>, MediaError>;
    fn negotiated_format(&self) -> VideoPixelFormat;
    fn hdr_metadata(&self) -> Option<HdrMetadata>;
    fn stats(&self) -> &DecodeStats;
}
```

Backend priority per platform (direct platform APIs first — they emit
exactly the handles the import path already consumes):

| OS | Priority chain |
|---|---|
| macOS | `objc2-video-toolbox` → `ffmpeg-next` hwaccel → software |
| Windows | MF `IMFSourceReader`+D3D11 → `mpv-engine` escape hatch → `ffmpeg-next` D3D11VA → software |
| Linux | `cros-libva` → GStreamer `va`/`memory:DMABuf` appsink → `gpu-video` (Vulkan Video, H.264) → `ffmpeg-next` VAAPI → software |

`mpv-engine` (proven `ExportedFrame::into_wgpu_texture` on all three
desktops) and GStreamer are retained as optional "play anything"
backends, never the default — heavy runtime deps and `LC_NUMERIC`
constraints.

### 4.2. Multi-Plane Import Fix

`ImportTextureDescriptor` gains `plane_index`; NV12/P010 import becomes
two `wgpu::Texture`s (full-res R8/R16 Y + half-res Rg8/Rg16 UV) feeding
`VideoProcessor`'s existing bi-planar path. Applies uniformly: IOSurface
plane index, D3D11 array slice, dma-buf plane/layer offset.

### 4.3. HDR Metadata Flow

`HdrMetadata` maps decoder side-data (VT `CMFormatDescription`
extensions, MF `MF_MT_*` attributes, VAAPI parsed SEI, FFmpeg
`AV_FRAME_DATA_*`) into `VideoPipelineUniforms` (`eotf_mode`,
`gamut`, `display_params`, filmic params) alongside the existing
`DisplayProfile`.

### 4.4. Frame Queue & Pacing

- Decode-ahead depth 2–3; last-buffer-drop under pressure.
- Skip when `now > pts + 1.5 × frame_interval`; count as dropped.
- `PresentMode::Mailbox` when `DisplayCapabilities` offers it.
- Public `drop_rate_pct()` and `cpu_utilization_pct(fps)` — the gate
  reads these, not external timing.

### 4.5. Feasibility Boundaries (documented, not hidden)

- **Pure-Rust software decode cannot hit 4K120** (`openh264`/`rav1d`
  are ~30–40ms/frame at 4K) — fallback only.
- Hardware tiers that can: Apple Silicon (VT 8K60+), NVIDIA
  Turing+/Ada+ (HEVC 4K120, AV1 on Ada), Intel Xe, AMD RDNA3+.
- **CI cannot verify the 4K120 gate** — it needs a self-hosted GPU
  runner with a real hardware decoder. Automated CI covers the noop/CPU
  paths; the 4K120 gate runs `#[ignore]`-gated on dedicated hardware.

## 5. Exit Criteria & Verification Gates

| Gate | Criterion | Verification |
|------|-----------|--------------|
| 4K120 playback | <0.1% frame drops, <1% CPU dispatch | `#[ignore]`-gated on dedicated GPU runner (H.264+HEVC+AV1 samples) |
| Decoder trait conformance | `MockDecoder` + each platform backend satisfy the trait contract | `martensite-media-test` suite |
| Multi-plane import | NV12 Y+UV imported as two textures, correct strides | noop-wgpu + platform `#[ignore]` tests |
| Software fallback | `ffmpeg-next` path plays without hwaccel | CI (CPU) |
| HDR metadata | `HdrMetadata` → uniforms; PQ and HLG samples tonemap correctly | Unit + golden frame |
| No regression | `import_cpu_memory` round-trip + `test-noop` interop suite stay green | CI |
| All gates | fmt, clippy, tests, doctests, docs, audit, deny, vet, benchmarks | Full CI suite |

## 6. Dependencies

- `objc2-video-toolbox` 0.3.x (macOS), `cros-libva` 0.0.x (Linux,
  `libva-dev` system dep — CI needs it like `libwayland-dev`),
  `ffmpeg-next` 9.x (fallback, `ffmpeg` system libs), `windows` 0.61
  feature extension. `mpv-engine`/`gstreamer-rs` optional-only.
- All gated behind `decoder-*` cargo features so the default build is
  unaffected.

---

## 7. Unsafe Code Policy

All decoder FFI lives in `martensite-media-platform` (already on the
allowed-unsafe list). `martensite-media` stays `#![forbid(unsafe_code)]`.
No new unsafe crates.

# Milestone Specification: v0.11.0 — Advanced Typography & Platform Accessibility

## 1. Executive Summary & Objectives
Milestone `v0.11.0` delivers an industrial-grade international typography and assistive technology engine for Martensite. It expands the layout and rendering subsystems to natively support complex bidirectional scripts (Unicode UAX #9), vertical writing modes (Unicode UAX #50 / `writing-mode: vertical-rl`), and OS-native system font fallback cascades across Windows, macOS, and Linux, eliminating missing-glyph tofu (`☐`). Concurrently, it elevates Martensite's accessibility architecture to complete AccessKit coverage across all widget primitives, real-time screen reader caret and selection tracking, dynamic live region announcements (`accesskit::Live`), comprehensive WCAG 2.2 AA/AAA conformance, and formal Section 508 VPAT (Voluntary Product Accessibility Template) certification.

---

## 2. Target Crates & Modules
- **`martensite-text`**:
  - `bidi`: Unicode BiDi algorithm implementation (UAX #9), embedding level resolution, directional run reordering, and mirrored character substitutions for mixed LTR/RTL text (Arabic, Hebrew, Persian).
  - `vertical`: Vertical layout pipeline (UAX #50), glyph orientation transforms, and OpenType vertical layout features (`vert`, `vrt2`, `vkrn`).
  - `cascade`: Native platform font fallback cascade resolvers (`DirectWrite` on Windows, `CoreText` on macOS, `Fontconfig` on Linux).
  - `shaping`: Swash & HarfBuzz complex shaping with ligatures, cursive attachment, mark positioning, and context-sensitive CJK line breaking (UAX #14 Kinsoku Shori).
  - `cache`: Tier 2 global LRU `TextShapeCache` expansion for BiDi runs, vertical glyph runs, and platform fallback chains.
- **`martensite-access`**:
  - `properties`: Extended accessibility properties including dynamic live region modes (`Live::Polite`, `Live::Assertive`), expanded roles, and state bitmasks.
  - `caret`: Screen reader caret tracking (`ActionData::SetTextSelection`), text boundary projection, and cursor navigation dispatch to assistive technologies (NVDA, JAWS, VoiceOver, Orca).
  - `tree`: Full incremental semantic tree synchronization covering 100% of base and composite widgets.
  - `compliance`: Automated WCAG 2.2 conformance verification suite (contrast, focus appearance, target size) and Section 508 VPAT telemetry.
- **`martensite-layout`**:
  - `vertical_flow`: Layout axis transposition for `writing-mode: vertical-rl` integrated into the two-pass Taffy layout bridge.
  - `bidi_rect`: Logical-to-physical coordinate mapping for inline RTL flow and selection geometry.

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Unicode Bidirectional Algorithm (UAX #9) & Complex Script Shaping
Mixed-direction text (such as English embedded within Arabic or Hebrew) requires strict multi-pass processing before layout and rasterization:
- **Paragraph Level & Run Splitting:** Text paragraphs are analyzed to determine the base direction (LTR or RTL). The algorithm evaluates explicit formatting codes (LRE, RLE, RLO, LRO, PDF, LRI, RLI, FSI, PDI) and resolves character embedding levels $0 \dots 125$.
- **L2 Visual Reordering:** Continuous runs with uniform direction are isolated, shaped via HarfBuzz / Swash, and visually reordered according to resolved embedding levels:
  $$\text{visual\_order}(R) = \text{reorder\_levels}(R, \text{base\_dir})$$
- **Mirrored Glyph Substitution:** Paired bracket and punctuation characters (e.g. parentheses, brackets, mathematical operators) in RTL contexts are mapped to their mirrored OpenType glyph counterparts.
- **Context-Sensitive Line Breaking (UAX #14):** Implements Kinsoku Shori rules for East Asian typography, forbidding line starts with closing brackets or punctuation and line ends with opening currency or quote markers.

### 4.2. Vertical Text Layout Pipeline (UAX #50 / `writing-mode: vertical-rl`)
For native typesetting of East Asian scripts (Japanese, Chinese, Korean) in traditional vertical orientation:
- **Character Orientation Classification:** Characters are categorized into vertical orientation classes per UAX #50:
  - *Upright ('U')*: CJK ideographs, full-width punctuation, and Kana render in their native upright orientation.
  - *Rotated ('R')*: Latin letters, digits, and European punctuation rotate $90^\circ$ clockwise.
  - *Transformed ('Tu')*: Characters requiring specialized vertical glyph representations (e.g. vertical em-dashes, brackets).
- **OpenType Feature Activation:** Automatically enables vertical layout features (`vert`, `vrt2`, `vkrn`) when shaping vertical text runs.
- **Coordinate Transposition:** Transforms the horizontal layout coordinate frame into a vertical-right-to-left frame:
  $$\begin{pmatrix} x' \\ y' \end{pmatrix} = \begin{pmatrix} W - (y + h) \\ x \end{pmatrix}$$
  Lines advance from right to left, and glyphs within each line advance from top to bottom along the ideographic central baseline.

### 4.3. Platform System Font Fallback Cascades
To guarantee that no user encounters missing-glyph tofu (`☐`), Martensite implements OS-native font fallback cascades via a `FontFallbackProvider` trait seam in `martensite-text::cascade`:
- **Trait Architecture:** The `FontFallbackProvider` trait abstracts the source of fallback families, allowing the static `PlatformCascadeResolver` (default) or native OS providers to be plugged into `InstalledFontFallbackResolver::with_provider`.
- **Windows (DirectWrite):** The `martensite-font-fallback` crate implements `DirectWriteFontFallback` using `IDWriteFontFallback::MapCharacters`, traversing the OS system font cascade (Segoe UI, Meiryo, Yu Gothic, Segoe UI Emoji, Nirmala UI, Malgun Gothic) based on script, culture, and character code points.
- **macOS (CoreText):** The `martensite-font-fallback` crate implements `CoreTextFontFallback` using `CTFontCreateForStringWithLanguage`, resolving missing characters through system-installed language fonts (PingFang SC, Hiragino Sans, Apple Color Emoji).
- **Linux (Fontconfig):** The `martensite-font-fallback` crate implements `FontconfigFontFallback` using `FcFontSort` with character set testing to match against FreeDesktop font configuration rules.
- **Unsafe Code Isolation:** The `martensite-font-fallback` crate uses `#![allow(unsafe_code)]` at the crate level for platform-specific FFI. The workspace-level `unsafe_code = "deny"` policy is preserved for all other crates; this is the narrowly scoped audited exception described in the v0.11.0 boundary decision.
- **Fallback Decision Cache:** `FallbackDecisionCache` caches resolved fallback chains keyed by `(script, locale, primary_family)`, invalidated by a font-system generation counter that increments whenever the font database is modified.
- **Malformed Font Hardening:** All `swash`/`ttf-parser` font-data access in the fallback path is wrapped in `catch_unwind` to guard against known malformed-font panic surfaces (swash #123–#126, ttf-parser RUSTSEC-2026-0192).
- **Canonical Shaping Path:** `Shaper::shape_with_options` is the single canonical shaping entry point used by the production `Text` widget, resolving the installed-font fallback chain, applying BiDi, and handling vertical writing modes.

### 4.4. Assistive Technology Caret Tracking & Dynamic Live Regions
To provide screen reader users (NVDA, JAWS, VoiceOver, Orca) with an experience equivalent to native platform controls:
- **Screen Reader Caret & Selection Tracking:** As the user navigates or edits text in text inputs, editors, or selectable displays, Martensite calculates the exact character bounding box in window coordinates and dispatches `accesskit::ActionData::SetTextSelection`. Screen readers speak individual characters, words, and deleted tokens synchronously with keyboard cursor navigation.
- **Dynamic Live Regions:** Accessible nodes expose dynamic live region attributes (`Live::Polite` for non-interruptive status updates, `Live::Assertive` for high-priority alerts). AccessKit's platform adapters emit live-region events natively when changed live nodes are included in `TreeUpdate`:
  - Windows: UI Automation `UIA_LiveRegionChangedEventId`.
  - macOS: NSAccessibility `NSAccessibilityAnnouncementRequestedNotification`.
  - Linux: AT-SPI2 `object:state-changed:showing` event on live region interfaces.
- **No Custom Live-Region Monitor:** Martensite does not duplicate live-region announcement logic. The previous `LiveRegionMonitor` was removed because AccessKit's platform adapters already handle live-region notifications natively; exposing a custom monitor would freeze an implementation detail before v1.0.
- **Accessibility Text Pattern:** Exposes standard UI Automation `ITextProvider` and `ITextRangeProvider` interfaces on text widgets to enable navigation by character, word, line, and document.
- **Hybrid Semantic Tree Sync:** `SemanticTreeSync` uses a two-tier synchronization strategy: dirty-flag early-exit (fast path) when no nodes have `DIRTY_A11Y` set and the node count matches the snapshot, and fingerprint validation (slow path) when dirty flags exist or the node count changed. This avoids the unconditional `O(n)` fingerprint scan on clean frames while still detecting unflagged mutations, removals, and reparenting.
- **Poison-Free Bridge:** The `MartensiteAccessBridge` uses `parking_lot::Mutex` instead of `std::sync::Mutex`, eliminating the risk of mutex poisoning after a panic while holding the lock.
- **WCAG Contrast Sanitization:** The `relative_luminance` function sanitizes NaN/inf color channels to `0.0` before clamping, preventing silent `false` returns from contrast checks involving invalid colors.

### 4.5. WCAG 2.2 AA/AAA Conformance & Section 508 VPAT Compliance
Martensite incorporates automated accessibility auditing and guarantees compliance with global standards:
- **Contrast Ratios:**
  - WCAG 2.2 Level AA: Minimum contrast ratio of $4.5:1$ for normal text, $3.0:1$ for large text ($\ge 18\text{pt}$ or $\ge 14\text{pt}$ bold), and $3.0:1$ for UI components and graphical objects.
  - WCAG 2.2 Level AAA: Enhanced contrast ratio of $7.0:1$ for normal text and $4.5:1$ for large text.
- **Focus Appearance (Level AAA / Criterion 2.4.13):** Focus indicators must have an area at least as large as a 2 CSS pixel solid border around the component and achieve a minimum contrast ratio of $3.0:1$ against unfocused states.
- **Target Size (Minimum / Criterion 2.5.8):** All interactive targets satisfy a minimum size of $24 \times 24$ CSS pixels or provide equivalent spacing.
- **Section 508 VPAT Certification:** Automated generation of an Information and Communication Technology (ICT) Accessibility Conformance Report based on the Voluntary Product Accessibility Template (VPAT 2.5 Rev), certifying conformance with Section 508 Standards for EIT.

## 6. Risk Matrix & Mitigations
| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| System font fallback COM/IPC calls cause UI thread stutter | Medium | High | Asynchronously query and resolve fallback chains on worker threads; pre-warm common script fallback chains at startup. |
| Memory overhead from deep BiDi run fragmentation | Low | Medium | Use small-vector allocation (`SmallVec<[BidiRun; 8]>`) to handle typical paragraphs entirely on the stack. |
| Rapid signal updates spam assistive technology live regions | Medium | Medium | Implement an 80ms event-coalescing window for `Live::Polite` notifications to avoid overwhelming audio speech queues. |
| Incompatible vertical font metrics in third-party OpenType fonts | Low | Medium | Provide fallback vertical advance synthetic emulation derived from horizontal em-box dimensions when `vert` metrics tables are absent. |

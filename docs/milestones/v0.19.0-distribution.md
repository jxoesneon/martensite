# Milestone Specification: v0.20.0 — Distribution & Developer Experience

## 1. Executive Summary & Objectives

Milestone `v0.20.0` delivers end-user distribution artifacts, native OS installers,
and automated release delivery pipelines for the `cargo-martensite` developer toolchain
and the `widget_catalog` reference application.

**Status: Ratified.** By architectural consensus, Distribution and the Developer
Experience Initiative (workstreams W1–W8) are unified under the `v0.20.0` release slot.
Shipping native installers and signed distribution infrastructure prior to `v1.0.0`
proves the release pipeline end-to-end and provides binary distribution channels for
app developers on Windows, macOS, and Linux.

---

## 2. Target Crates, Artifacts & Manifests

- `tools/cargo-martensite` (developer CLI binary for distribution)
- `examples/widget_catalog` (comprehensive widget showcase and reference vehicle)
- `packaging/windows/wix/main.wxs` (WiX MSI installer manifest)
- `packaging/windows/build-msi.ps1` (PowerShell WiX build driver)
- `packaging/macos/build-dmg.sh` (macOS DMG packaging script)
- `packaging/linux/flatpak/org.martensite.WidgetCatalog.yaml` (Flatpak manifest & desktop integration)
- `scripts/generate-update-manifest.py` (Ed25519-signed update manifest generator)
- `.github/workflows/release-distribution.yml` (multi-platform release matrix, SLSA provenance, GitHub Releases)

## 4. Architectural Deliverables & Implementation Specifications

### 4.1. Pre-built Standalone Binaries

Release binaries are compiled in release mode with optimization flags (`opt-level = 3`, `codegen-units = 1`)
and packaged into flat archives with license files:
- **Windows:** `.zip` containing `cargo-martensite.exe`, `widget_catalog.exe`, `LICENSE-APACHE`, `LICENSE-MIT`.
- **Unix:** `.tar.gz` containing `cargo-martensite`, `widget_catalog`, `LICENSE-APACHE`, `LICENSE-MIT`.
- Supported target matrix:
  - `x86_64-pc-windows-msvc` (Windows x64)
  - `x86_64-apple-darwin` (macOS Intel)
  - `aarch64-apple-darwin` (macOS Apple Silicon)
  - `x86_64-unknown-linux-gnu` (Linux x64 glibc)
  - `aarch64-unknown-linux-gnu` (Linux ARM64 glibc)

### 4.2. Native Installers

#### Windows: WiX `.msi` (`packaging/windows/wix/main.wxs`)
- **Package Identity:**
  - Manufacturer: `Martensite Project`
  - UpgradeCode: `4C7A8F3E-94C3-4E86-9A1D-E1D96D2BC8E1`
  - InstallScope: `perMachine` (`C:\Program Files\Martensite\bin`)
- **Components & Features:**
  - `cargo-martensite.exe` and `widget_catalog.exe` registered with 64-bit component definitions (`Win64="yes"`).
  - Start Menu shortcuts in `ProgramMenuFolder\Martensite` for `Martensite Widget Catalog`.
  - System `PATH` registration inserting `[BINDIR]` into the system environment variable table so `cargo martensite` and `widget_catalog` are directly invokable.
- **Build Automation (`packaging/windows/build-msi.ps1`):**
  - Auto-detects WiX Toolset v4/v5 (`wix build`) or WiX v3 (`candle.exe` + `light.exe` with `WixUIExtension`).
  - Verifies presence of built binaries or triggers release cargo build.
  - Emits `martensite-<version>-<arch>.msi` and computes SHA-256 hash.

#### macOS: Styled `.dmg` (`packaging/macos/build-dmg.sh`)
- **Bundle Architecture:**
  - Assembles `Martensite Widget Catalog.app` with `Contents/Info.plist`, `Contents/MacOS/widget_catalog`, and bundled helper `cargo-martensite`.
  - Configures high-DPI scaling (`NSHighResolutionCapable`), minimum macOS version (`11.0 Big Sur`), and discrete GPU switching (`NSSupportsAutomaticGraphicsSwitching`).
- **Disk Image Layout:**
  - Staging includes `/Applications` symlink for frictionless drag-and-drop installation.
  - Dual creation strategy: uses `create-dmg` for custom window geometry and icon layout when installed; falls back to native `hdiutil create -ov -format UDZO`.
- **Security & Notarization:**
  - Hardened runtime code signing (`codesign --force --options runtime --deep`).
  - Apple notarization submission via `xcrun notarytool` and ticket stapling via `xcrun stapler` when credentials are provided; falls back to unsigned ad-hoc builds for testing.

#### Linux: Flatpak (`packaging/linux/flatpak/org.martensite.WidgetCatalog.yaml`)
- **Runtime Environment:**
  - App ID: `org.martensite.WidgetCatalog`
  - Runtime / SDK: `org.freedesktop.Platform` / `org.freedesktop.Sdk` version `24.08`.
  - SDK Extension: `org.freedesktop.Sdk.Extension.rust-stable`.
- **Sandbox Configuration (finish-args):**
  - Display servers: `--socket=wayland`, `--socket=fallback-x11`.
  - GPU acceleration: `--device=dri` for hardware WGPU and Vulkan rendering.
  - Shared memory: `--share=ipc`.
  - Desktop integration: `--talk-name=org.freedesktop.Notifications`, `--filesystem=xdg-run/dconf`.
- **Desktop Packaging:**
  - XDG desktop entry: `org.martensite.WidgetCatalog.desktop`.
  - AppStream MetaInfo: `org.martensite.WidgetCatalog.metainfo.xml`.
  - Vector icon: scalable SVG `org.martensite.WidgetCatalog.svg`.
  - Single-file export helper: `build-flatpak.sh` driving `flatpak-builder` and `flatpak build-bundle`.

### 4.3. Cryptographic Update Manifest & Verification

- **Schema:** JSON update manifest adhering to `https://martensite.dev/schema/update-manifest-v1.json`.
- **Manifest Generator (`scripts/generate-update-manifest.py`):**
  - Aggregates all distribution archives, installers, SHA-256 digests, and file sizes.
  - Generates unified `SHA256SUMS.txt`.
  - Signs `update-manifest.json` using RFC 8032 Ed25519 asymmetric cryptography.
  - Outputs `update-manifest.json.sig` and public verification key `update-manifest.pub`.
  - Immediately validates signature mathematically before deployment.
- **Client Verification Contract:**
  - `cargo-martensite self-update` and external update agents fetch `update-manifest.json` + `update-manifest.json.sig`, verify against the pinned release public key, match SHA-256 digests, and atomically unpack new binaries.

### 4.4. CI/CD Release Distribution Pipeline (`.github/workflows/release-distribution.yml`)

- **Triggers:** Tag pushes (`v*.*.*`) or manual `workflow_dispatch`.
- **Job Matrix:**
  - Concurrently compiles 5 architecture/OS legs.
  - Packages `.zip` and `.tar.gz` standalone archives.
  - Executes native installer builds on target host OS runners (Windows runner builds WiX MSI, macOS runner builds DMG).
- **Consolidation & Attestation:**
  - Aggregates all build artifacts into a centralized `dist/` staging workspace.
  - Emits SLSA Level 3 build provenance via `actions/attest-build-provenance@v2` (cryptographically bound to GitHub's OIDC issuer).
  - Generates signed update manifests and checksums.
  - Uploads all release assets atomically to GitHub Releases using `softprops/action-gh-release@v3`.

## 5. Exit Criteria & Verification Gates

1. **Installer Compilation:**
   - Windows WiX `.msi` packages cleanly via `packaging/windows/build-msi.ps1`.
   - macOS `.dmg` generates valid UDZO disk image with `/Applications` link via `packaging/macos/build-dmg.sh`.
   - Linux Flatpak manifest validates against AppStream and flatpak schemas.
2. **Update Manifest Verification:**
   - `scripts/generate-update-manifest.py` generates valid JSON, valid `SHA256SUMS.txt`, and verifiable Ed25519 signature.
3. **Release Pipeline Integrity:**
   - `.github/workflows/release-distribution.yml` passes workflow syntax validation, defines valid matrix legs, specifies SLSA Level 3 attestation permissions (`id-token: write`, `attestations: write`), and uploads all artifacts.
4. **Standard Workspace Gates:**
   - `cargo fmt --all -- --check` clean.
   - `cargo clippy --workspace --all-targets -- -D warnings` clean.
   - Workspace tests pass.

## 6. Risk Matrix & Mitigations

| Risk Description | Probability | Severity | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| macOS signing/notarization credentials absent in external PRs | High | Medium | `build-dmg.sh` provides explicit unsigned fallback mode and documents required GitHub secrets. |
| WiX Toolset version fragmentation (v3 vs v4/v5) | Medium | Low | `build-msi.ps1` implements dual-mode discovery supporting both WiX v4+ (`wix build`) and WiX v3 (`candle`/`light`). |
| Update manifest signing key exposure | Low | Critical | Private key stored in GitHub Actions encrypted secrets; manifest verification validates public key with zero private key leak. |
| Inconsistent checksum formatting across OS utilities | Low | Low | Unified Python generator formats standard GNU coreutils `<sha256>  <filename>` format with LF endings. |
